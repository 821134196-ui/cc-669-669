# 预订到货批次分配系统

商品分批到货，按预订付款顺序自动分货；客户可查询等待顺位、分到的批次与取货期限；
逾期未取 / 拒收 / 放弃本批会把商品退回原批次并自动通知下一顺位。

技术栈：TypeScript · NestJS · React (Vite) · Prisma · SQLite。支付与通知均为本地模拟。

## 一条命令启动

```bash
npm install
npm start
```

- 前端（运营台 + 客户查询）：http://localhost:5173
- 后端 API：http://localhost:3001

`npm start` 会自动完成 Prisma Client 生成、数据库迁移与种子数据，然后并行启动前后端。

种子数据（重置用 `npm run db:setup` 或 `npm run db:reset`）：

- 1 个商品「周年限定手办」，5 个预订订单（订单号 `PO-SEED-001` ~ `PO-SEED-005`，按付款时间排序）
- 批次 `B20261005-01`（2 件，正常，已分给前 2 位）
- 批次 `B20261006-02`（3 件，**质检暂停**，不参与分配；运营台点“恢复并补排”后会自动分给后续顺位）

## 页面说明

**客户查询**：输入订单号可看到

- 当前等待顺位（前面还有几人、队列总人数）
- 分到的批次号、分货顺位、第几次分到货
- 取货截止时间与剩余小时数
- 「放弃本批次」按钮：放弃后该件顺延给下一顺位，本人保留排队资格，且不会被分回刚放弃的批次
- 历史分配记录（待取货 / 已取货 / 逾期退回 / 已拒收 / 已放弃）与通知短信

**运营台**：

- 登记实收到货批次（批次号、实收数量、到货回执单号）→ 立即按顺位自动分货
- 同一到货回执重复提交不会再次增加库存（幂等）
- 批次质检暂停 / 恢复；暂停期间不参与分配，恢复时立即补排
- 队列总览：等待顺位、当前批次、取货期限、确认取货 / 拒收 / 模拟逾期
- 模拟支付下单、实时通知流（每 5 秒刷新）
- 取货期限默认 48 小时（`server/.env` 的 `PICKUP_DEADLINE_HOURS`），
  后端每 30 秒扫描到期分配自动顺延；页面上的「模拟逾期」可立即触发该流程

## 分货规则

1. 队列顺序固定为 `付款成功时间 ASC, 订单号 ASC`，任何接口都无法人工插队。
2. 同一产品的所有库存变动走**产品级互斥锁**串行化；事务内再用条件
   `UPDATE ... WHERE allocatedQty + n <= receivedQty AND paused = 0` 兜底，
   并发到货 / 并发结算都不可能分超实收数量。
3. 逾期未取、拒收、客户放弃本批：商品退回**原批次**（占用 -1），
   立刻重算队列并通知下一顺位；客户保留排队资格等待后续批次。
4. 客户放弃 / 逾期 / 拒收过的批次对该客户做一次性排除，避免刚放弃又立刻分回同一批。
5. 取货完成：实收与占用各减 1（商品真实出库），订单离开队列。
6. 质检暂停批次完全不参与分配（条件扣减带 `paused = 0` 双保险），恢复时触发补排。

## 场景验证

```bash
npm run test:engine
```

覆盖：稳定排序（同付款时间按订单号）、并发到货不超卖、逾期/拒收/放弃回补与顺位推进、
放弃后不再分回同批且继续排队、取货出库、暂停批次跳过与恢复补排、重复回执幂等、
10 个批次并发登记的高并发压力。
